# 第一阶段与 K-way 阶段的复现核查

两阶段多专家组使用相同的核心训练方法，但实际运行协议不同：第一阶段是 **seed=11、100 轮余弦日程**，K-way 阶段是 **seed=42、60 轮余弦日程**。后者属于新协议下的对照实验，不能作为第一阶段数值结果的直接复现。

对保存的代码、配置、权重来源及标准置信度测试实现进行对照，并执行同协议短步数检查后，**未发现多专家训练逻辑的迁移错误**。现有结果也不支持“潜在域的未见域泛化失效”：其七域平均下降主要来自两个源域，而未见四域平均值仍提高。

## 3. 真正改变的训练设置

| 项目 | 第一阶段 Unique 两组 | 当前阶段多专家两组 |
|---|---|---|
| seed | 11 | 42 |
| 训练轮数 | 100 | 60 |
| 余弦学习率周期 | 100 | 60 |
| 最佳权重轮次 | 两组均 31 | 两组均 27 |
| 训练图/源验证图 | 12,742 / 1,592 | 相同 |
| 每轮步数、总 batch | 1,062 / 12 | 相同 |
| 规范去重图片顺序 | 同一记录顺序 | 相同 |
| 初始预训练文件 | `model_data/yolov8_s.pth` | 相同 |
| 对应域的专家权重及 best 信息 | 国家三个、潜在两个 | 相同 |
| Student 优化器 | SGD、momentum=0.937、Nesterov、weight_decay=0.0005 | 相同 |
| 学习率峰值/最小值 | 0.001875 / 0.00001875 | 相同 |
| 判别器优化器 | Adam、lr=1e-5、betas=(0.9,0.999) | 相同 |
| 域对抗 | feat3、LSGAN、权重 0.7、Student 后更新 D | 相同 |
| Triplet | feat3/feat2、类别 batch-hard、权重 0.3 | 相同 |
| 梯度裁剪 | Student 范数 2.0 | 相同 |
| 最佳权重选择 | 最低源验证检测损失的 Student EMA | 相同 |

### seed 改变了完整初始化

初始预训练文件相同，不等于完整 Student 初始化相同。实际初始化会保留形状不匹配参数的随机初值；本模型有六个未加载的参数张量：

`cv3.0.2.weight/bias`、`cv3.1.2.weight/bias`、`cv3.2.2.weight/bias`。

以 seed=11 与 seed=42 重新构造并加载预训练文件后，逐项比较确认：这六个分类输出层张量不同，其余 Student 状态张量相同。判别器初始化使用 `seed + 100 + domain`，同样随 seed 改变；每轮 shuffle 和数据增强随机序列也改变。

### 60 轮不是 100 轮训练的前 60 轮

两阶段都调用 `get_lr_scheduler('cos', lr, min_lr, args.epochs)`。周期直接影响前半程的学习率：

| 实际轮次（从 1 起） | 100 轮日程 LR | 60 轮日程 LR |
|---|---:|---:|
| 1 | 0.000187500 | 0.000187500 |
| 4 | 0.001875000 | 0.001875000 |
| 20 | 0.001739883 | 0.001501113 |
| 27 | 0.001603158 | 0.001160915 |
| 31 | 0.001507682 | 0.000946875 |
| 60 | 0.000636065 | 0.000018750 |

第 27 轮 60 轮日程的学习率约低 **27.59%**。所以“第一阶段最佳在 31 轮，训练 60 轮应足够复现”这一推断不成立。要延续 100 轮轨迹，必须保留 100 轮调度周期，不能只保留足够大的实际轮数。

这些是已经证实的协议差异，但尚未分别运行 seed 与日程消融，不能将分数差异精确归因给其中某一项。

## 4. 新旧入口数值一致性检查

使用两阶段各自保存的训练定义、同一实际数据与专家权重，统一 **seed=11、epochs=100、batch=12、workers=8**，对国家域、潜在域分别执行 **3 个真实训练 batch（36 张训练图）及 13 张源验证图**。检查进程固定确定性 CUDA 算法，用于隔离后端算法选择造成的噪声。

当前入口增加的特征梯度诊断也在该检查中正常执行。之后逐项比较 Student、EMA 和全部判别器状态：

| 比较对象 | 国家域对照 | 潜在域对照 |
|---|---:|---:|
| Student 状态张量数量 | 355 | 355 |
| Student 不同张量数 | 0 | 0 |
| EMA 不同张量数 | 0 | 0 |
| 判别器状态张量数量 | 78 | 52 |
| 判别器不同张量数 | 0 | 0 |
| 所有比较张量最大绝对差 | 0 | 0 |
| total/detection/Triplet/critic/generator/validation loss 差值 | 全部 0 | 全部 0 |

这验证了已执行的三个优化步在相同协议下逐张量一致，并结合静态代码对照支持多专家实现迁移一致；它不等同于已经完成整段 100 轮数值复现。

脚本、日志和结果见 [reproduction_audit_20261015](reproduction_audit_20261015/)，数表见 [parity_results.json](reproduction_audit_20261015/parity_results.json)。

## 5. 测试标准是否仍有差异

本次标准复测使用的 `code/standard_utils_bbox.py` 与第一阶段标准复测的解码器副本逐字节相同；`utils/comparison_evaluation.py` 也相同。

两者均为 640 输入、直接缩放、标准类别 sigmoid 最大值、confidence=0.001、NMS IoU=0.5、无 TTA，VOC 连续 AP50、COCO 101 点 AP、maxDets=100，七域测试清单一致。YOLO 包装类的默认模型路径虽不同，但实际由命令传入对应 best 权重覆盖。

当前四组的第一次测试存在配置标记与实际解码不一致，使用了不确定性分数；本报告所有分数均来自已经完成的标准置信度复测，不混用首次测试结果。

## 6. 后续执行顺序

1. **若目标是完整复现第一阶段，先固定原协议**：seed=11、100 轮训练与100轮余弦日程、原 Unique 数据顺序、原专家和最低源验证 loss 选权重，使用标准置信度测试。先检查多专家两组的整段损失轨迹与原始结果，再评价 K-way。
2. **K-way 只改变预定的对抗方案**：在同样 seed=11、100轮日程下运行，与上述基线成对比较。当前 seed=42、60轮的四组结果保留，作为另一套协议的观测。
3. **源域与未见域指标分别报告**：七域平均反映混合表现，未见四域平均反映本项目的跨域泛化主指标；两者都保留，不能用七域排名替代未见域结论。
4. **复现确认后再评估稳定性**：以配对 seed 检查潜在域的源域损失和未见域收益能否重复。当前两套协议均观察到未见域平均优势，但不足以给出多seed稳定性或显著性结论。

本次未更改训练方法、聚类标签或历史权重；短步数检查产物与正式实验独立保存。
