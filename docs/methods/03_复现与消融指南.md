# 复现与后续组件消融

本页提供新运行目录的复现配方。主线采用Unique、seed11、100轮及100轮余弦日程、标准置信度七域测试。先固定现有K=2标签和专家，再替换待研究组件。

## 当前目录的路径适配

| 历史引用 | 当前归档位置 | 影响 |
|---|---|---|
| `latent_domain_analysis/` | `stage0-latent_domain_analysis/` | 训练helper、域CSV审计和部分配置仍使用旧路径 |
| `results/comparison_20261005_100ep/` | `stage1-latent-domain/comparison_20261005_100ep/` | 原启动脚本输出和JSON来源路径是历史地址 |
| 根目录`kway_comparison_..._时间戳/` | `stage2-k-way/kway_comparison_.../` | 历史screen脚本、快照bootstrap和部分报告链接仍含搬迁前地址 |
| 根目录`train_style_adv.py --experiment ...` | S1快照才有对应提前分发 | 当前根目录同名文件进入旧K=3软路由入口，不可照抄历史命令 |
| 根目录`new_experiments/kway_domain/launch.py` | 仍是seed42/60轮启动器 | 不能拿它默认启动100轮协议；worker/report也含旧固定值 |

这些入口仍保留原运行时的目录约定。复现时读取冻结快照，并在**新运行进程内**把旧数据别名映射至当前S0目录。已有历史JSON和代码快照保持原样。

## 1. 环境、数据与专家

- 检测环境：`/data4/czh/anaconda3/envs/yolo_dg/bin/python`，已记录Python3.10.20、torch2.1.1+cu121、CUDA12.1、RTX2080Ti；完整版本以各`run_manifest.json`为准。
- 聚类统计环境：`stage0-latent_domain_analysis/.venv/bin/python`，原记录scikit-learn1.5.2、NumPy1.26.4。它与检测环境职责不同。
- 初始化：`model_data/yolov8_s.pth`；类别：`model_data/rdd_classes.txt`。
- 数据：保留`datasets/RDD2022/ImageSets`原列表；潜在域使用S0的`domain_splits/`；图像TXT中的真实路径可能解析到`/data4/czh/code/yolov8-pytorch-master/...`，这是实际记录路径，不应批量改写。
- 专家：`../yolov8-pretrain/results/expert_pretrain_20261004_200ep/{Japan,India,United_States,Cluster_0,Cluster_1}/best_epoch_weights.pth`。改训练组件时通常直接复用这些专家；改域划分或标签编号时必须重新确认专家映射。

Student加载预训练时按参数形状筛选；四类输出的`cv3.0.2`、`cv3.1.2`、`cv3.2.2`各自weight/bias共六个张量不在兼容加载集合中，保留由seed决定的随机初值。相同预训练文件不等于不同seed下的完整Student初始化相同。D另用`seed+100+domain`初始化；K-way单头用`seed+100`。

## 2. S0复用与从头生成

后续检测组件消融直接复用S0已完成的scaler、中心、固定CSV及TXT，避免把聚类变化混入组件变化。现有已完成缓存有覆盖保护，不应在原目录重复执行提取与导出。

需要从头重建S0时，使用独立工作目录，复制S0的`.py`文件，保持实际数据与权重位置不变。执行顺序为：

```text
extract_features.py
→ select_k.py
→ analyze_clusters.py --candidate 2（并按需检查其他候选）
→ robustness_checks.py
→ 确认FINAL_K
→ analyze_clusters.py
→ extract_val_features.py
→ export_domain_splits.py
```

复制到新工作目录后，`config.py`按脚本位置推导`PROJECT`，需在进程内设置真实项目位置。例如执行一个步骤的模板：

```bash
PROJECT=/data4/czh/yolov8-cluster/yolov8-hard-clustering
cd "$PROJECT"
ANALYSIS_WORK="$PROJECT/reproductions/latent_analysis_new"
mkdir -p "$ANALYSIS_WORK"
cp "$PROJECT"/stage0-latent_domain_analysis/*.py "$ANALYSIS_WORK/"
export PROJECT ANALYSIS_WORK
"$PROJECT/stage0-latent_domain_analysis/.venv/bin/python" -u - <<'PY'
import os, runpy, sys
from pathlib import Path
p = Path(os.environ['PROJECT'])
w = Path(os.environ['ANALYSIS_WORK'])
sys.path.insert(0, str(w))
import config as C
C.PROJECT = p
C.WEIGHTS = p/'model_data/yolov8_s.pth'
C.MANIFEST_ROOT = p/'datasets/RDD2022/ImageSets'
# C.ROOT/FEATURES/RESULTS/FIGURES仍指向新工作目录。
sys.argv = ['extract_features.py', '--device', 'cuda:0', '--batch-size', '16', '--workers', '4']
runpy.run_path(str(w/'extract_features.py'), run_name='__main__')
PY
```

后续步骤沿用同一新工作目录和同样的PROJECT适配，更换`sys.argv`及脚本名。选择K和稳健性步骤仅使用缓存；验证分配仅使用训练中心。若研究K本身，应重新审阅候选并修改**新工作目录**的FINAL_K；不把已有K=2确认当作其他设置的结论。

## 3. 适配当前归档的统一训练/测试入口

下面创建的是**新复现目录中的进程入口**。它不修改项目训练源文件；调用S2-100冻结快照中的模块，其中`utils/comparison_training.py`与第一阶段保存的核心实现相同。

```bash
PROJECT=/data4/czh/yolov8-cluster/yolov8-hard-clustering
cd "$PROJECT"
PYTHON=/data4/czh/anaconda3/envs/yolo_dg/bin/python
REPLAY_DIR="$PROJECT/reproductions/seed11_100ep_example"
mkdir -p "$REPLAY_DIR"
cat > "$REPLAY_DIR/replay.py" <<'PY'
from pathlib import Path
import importlib, sys

PROJECT = Path('/data4/czh/yolov8-cluster/yolov8-hard-clustering')
S0 = PROJECT/'stage0-latent_domain_analysis'
SNAP = PROJECT/'stage2-k-way/kway_comparison_100ep_seed11_20261015/source_snapshot'
sys.path.insert(0, str(SNAP))

class DataRoot(type(PROJECT)):
    def __truediv__(self, key):
        aliases = {
            'latent_domain_analysis/domain_splits': S0/'domain_splits',
            'latent_domain_analysis/results/final_cluster_labels.csv': S0/'results/final_cluster_labels.csv',
        }
        return aliases.get(str(key), PROJECT/key)

import utils.comparison_training as training
training.ROOT = DataRoot(PROJECT)
training.EXPERT_ROOT = PROJECT.parent/'yolov8-pretrain/results/expert_pretrain_20261004_200ep'
import utils.comparison_evaluation as evaluation
evaluation.ROOT = PROJECT
module_name = sys.argv[1]
sys.argv = [module_name] + sys.argv[2:]
importlib.import_module(module_name).main()
PY
export CUDA_DEVICE_ORDER=PCI_BUS_ID
export OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MPLBACKEND=Agg
```

每次完整重跑使用新的`REPLAY_DIR`，不复用已有正式输出。`--smoke_steps 3`会生成短跑产物，必须放到单独的`checks/`，不能把其best当作正式训练结果。

### 重建第一阶段五组方案

逐个将`EXPERIMENT`设为`baseline`、`country_repeat`、`latent_repeat`、`country_unique`、`latent_unique`。GPU按实际空闲情况选择。

```bash
EXPERIMENT=latent_unique
CUDA_VISIBLE_DEVICES=0 "$PYTHON" -u "$REPLAY_DIR/replay.py" utils.comparison_training \
  --experiment "$EXPERIMENT" --results_path "$REPLAY_DIR/stage1" \
  --epochs 100 --seed 11 --batch_size 12 --num_workers 8
```

这个模块可通过上面的`.main()`调用进入原五组实现；它本身没有直接模块运行的`__main__`调用，不应把命令简写成`python -m utils.comparison_training`。

### 重建01～04四组方案

同协议复现可直接使用原已标定系数；改变初始化、特征层或判别器结构时，按同一源训练方法重新标定并另存记录。

| EXPERIMENT | alpha_domain | 结构 |
|---|---:|---|
| 01_country_multi_unique | 0.7 | 国家多专家LSGAN |
| 02_latent_multi_unique | 0.7 | 潜在多专家LSGAN |
| 03_country_kway_unique | 0.01306498680128547 | 国家Hard CE+GRL |
| 04_latent_kway_unique | 0.014579329162945357 | 潜在Hard CE+GRL |

```bash
EXPERIMENT=04_latent_kway_unique

CUDA_VISIBLE_DEVICES=3 "$PYTHON" -u "$REPLAY_DIR/replay.py" new_experiments.kway_domain.training \
```

要为新配方标定，可调用同一入口的`new_experiments.kway_domain.verify --seed 11 --epochs 100 --output 新记录.json`。它同时运行源batch梯度和冻结特征可学习性检查；不读取目标测试分数。四卡并行时为四组分别使用独立GPU、独立screen及日志，并记录实际命令。不要直接运行搬迁前的`launch_logs/*.sh`；其中的脚本地址和输出地址仍是历史位置。

### 标准置信度七域测试

训练完成后使用同一个快照中的`StandardConfidenceYOLO`，而不是当前根目录`get_map_new.py`默认依赖的旧不确定性解码器：

```bash
CUDA_VISIBLE_DEVICES=3 "$PYTHON" -u "$REPLAY_DIR/replay.py" new_experiments.kway_domain.evaluation \
  --weights "$REPLAY_DIR/stage2/$EXPERIMENT/best_epoch_weights.pth" \
  --output "$REPLAY_DIR/stage2/$EXPERIMENT/testing_standard" \
  --experiment "$EXPERIMENT" --seed 11
```

第一阶段重跑只需把权重路径换为`stage1/$EXPERIMENT`。正式测试共七域9,433张图；主指标为各域VOC AP50之和除以7，不能把全部图像合并算一次AP，也不能按各域图像数加权。VOC/COCO使用不同定义，应分别保存。

本模板直接调用训练和标准测试模块。对新输出的七域均值可按以下方式读取，无需使用绑定历史套件目录的旧worker/report：

```bash
"$PYTHON" - "$REPLAY_DIR/stage2/$EXPERIMENT/testing_standard/summary.csv" <<'PY'
import csv, sys
with open(sys.argv[1]) as f:
    rows = list(csv.DictReader(f))
assert len(rows) == 7 and sum(int(r['images']) for r in rows) == 9433
for key in ['voc_map50', 'coco_map50', 'coco_map50_95']:
    print(key, f'{sum(float(r[key]) for r in rows)/7*100:.4f}%')
PY
```

断点恢复：四组`training.py`支持`--resume`，须保留该运行自己的`training_state.pt`和相同配置；五组原`comparison_training.main()`没有完整恢复参数。仅加载`last_epoch_weights.pth`不构成忠实恢复，因为缺少优化器、D、EMA计数和随机状态。

## 4. 复现验收

| 验收层次 | 可用证据 | 能说明什么 |
|---|---|---|
| 方法与配置 | 快照、run_config、命令、数据/专家映射 | 按同一配方实现 |
| 数值轨迹 | 相同batch的输出、梯度、优化后权重 | 指定条件下计算一致 |
| 完整实验结果 | 相同选权重规则和测试协议的100轮运行 | 终值与趋势是否重复 |
| 稳定性 | 同协议配对多seed | 差异相对随机波动是否稳定 |

同seed不是逐位一致的保证。正式入口会在seed设置后开启`cudnn.benchmark=True`；若目标是定位数值分叉，应在同一GPU上，使用项目已有[确定性对照包装器](../../tools/run_deterministic_parity.py)固定后端后比较早期轨迹。确定性设置本身也须记录，不能把短步数对照结论扩大成完整训练等效。

## 5. 后续消融应如何控制变量

当前四组不是所有组件的独立消融全集。对新组件应先明确输入、损失、梯度和训练成本边界，再实现相应开关和对照；下表中未完成的对照属于后续实验设计。

| 研究问题 | 合适对照 | 必须保持一致 | 当前状态 |
|---|---|---|---|
| 潜在域整套设定是否有益 | 国家Unique vs 潜在Unique | 图片预算、初始化、日程、测试口径 | 已有，但同时改变K、专家和Triplet池 |
| 完整K-way替换的成本取舍 | 01 vs03；02 vs04 | 同域划分、检测、Triplet、seed/日程 | 已有，不能归因为仅改变头数 |
| Triplet是否贡献精度 | 固定结构下w_tri=0 vs0.3 | 域标签和域对抗不变 | 主四组未独立验证 |
| 域对抗是否有效 | 检测+Triplet vs完整对抗 | 同一域池/采样 | 主四组未独立验证；零权重数值检查不等于精度实验 |
| GRL是否必要 | CE分支无反向 vsGRL | 分类器、系数、batch、其他损失 | 需新控制实验，不与其他hard_kway历史分支混称 |
| 聚类K是否影响下游 | 固定配方下改变K | 表示、筛选准则、训练预算；匹配专家 | K选择已有无监督证据，检测K扫描尚无对应主表 |
| 新增组件是否有益 | 明确基线 vs基线+组件 | 优先固定K=2硬标签、100轮协议、标准测试 | 待设计 |

若想隔离“域标签”本身，应单独考虑固定头数/专家预算、Triplet域池以及采样分布的设计，而不是将国家3域到潜在2域的全部变化归因于聚类。

模型选择坚持源验证检测loss。七域VOC是报告的主要效果指标，不用它挑选epoch、调系数或筛选seed；若形成新的模型选择规则，应在新实验前明确并一致执行。
